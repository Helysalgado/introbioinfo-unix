# Construcción de la Sesión S25 — Separar el procedimiento de los datos

Vamos a continuar el desarrollo del curso universitario de **Bioinformática** para estudiantes de **primer semestre de la Licenciatura en Ciencias Genómicas**.

Antes de escribir cualquier contenido debes estudiar cuidadosamente:

1. `README.md`
2. `guia-generacion-unidad.md`

Después revisa completamente:

- Unidad 4
- S23
- S24

S25 debe ser una continuación natural de S24.

No debe sentirse como una sesión nueva.

Debe sentirse como el siguiente paso inevitable.

---

# Filosofía

Este NO es un curso de Bash.

Shell únicamente proporciona herramientas para construir análisis bioinformáticos reutilizables.

Nunca enseñar:

- variables;
- parámetros;
- if;

porque existen.

Cada elemento debe aparecer únicamente cuando resuelva una necesidad científica.

---

# Contexto narrativo

En S24 el estudiante logró construir su primer script.

Ahora puede ejecutar el análisis completo mediante una sola orden.

Pero aparece inmediatamente una nueva limitación.

Todo sigue dependiendo del mismo genoma.

El script contiene:

- nombres de archivos;
- rutas;
- directorios;
- salidas.

Todo está escrito dentro del procedimiento.

Eso significa que:

cada nuevo genoma

↓

requiere editar el script.

Ese problema debe convertirse en el hilo conductor de S25.

---

# Cambio conceptual

En S24 el estudiante aprendió:

```text
Protocolo

↓

Script
```

Ahora aprenderá:

```text
Procedimiento

↓

Datos

↓

Separarlos
```

Este es el verdadero objetivo.

Las variables únicamente son una consecuencia.

---

# Propósito de la sesión

Que el estudiante aprenda a distinguir claramente:

qué parte del análisis permanece constante

y

qué parte cambia para cada genoma.

Al finalizar comprenderá que un procedimiento científico debe describir el análisis,

no los datos particulares.

---

# Competencia que desarrolla

Hasta ahora el estudiante aprendió a:

✔ guardar un procedimiento

✔ automatizar un análisis

Ahora aprenderá a:

✔ separar procedimiento y datos

✔ construir herramientas reutilizables

✔ validar entradas

✔ recibir información desde fuera del procedimiento

---

# Filosofía de la sesión

No introducir primero variables.

Primero mostrar el problema.

Ejemplo:

Hoy el script contiene:

```text
data/source/anotacion.gff3
```

Mañana llega otro genoma.

Ahora el estudiante tiene dos opciones.

Opción 1

Editar el script.

Opción 2

Mantener el procedimiento igual

y cambiar únicamente los datos.

Toda la sesión gira alrededor de esa decisión.

---

# Preguntas científicas

Toda la sesión debe responder preguntas como:

- ¿Por qué un procedimiento no debería contener el nombre del genoma?
- ¿Qué parte del análisis depende del organismo?
- ¿Qué parte permanece igual?
- ¿Cómo reutilizo exactamente el mismo análisis sobre otro conjunto de datos?
- ¿Cómo detecto que falta una entrada antes de comenzar?

---

# Herramientas nuevas

Introducir únicamente las necesarias.

Variables.

Parámetros.

`$1`

`$2`

`if`

`exit`

Mensajes de error.

No enseñar sintaxis por separado.

Cada elemento aparece cuando el estudiante descubre que lo necesita.

# Prácticas

Todas deben utilizar el proyecto desarrollado desde la Unidad 4.

Nunca inventar ejemplos artificiales.

El estudiante modificará exclusivamente su propio script.

Las actividades deben incluir:

- identificar qué rutas deberían dejar de estar escritas dentro;
- convertirlas en parámetros;
- ejecutar el mismo script sobre distintos conjuntos de datos;
- provocar errores de entrada;
- validar mensajes;
- comparar resultados contra S24.
