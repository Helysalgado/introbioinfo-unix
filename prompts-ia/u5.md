
# Unidad 5. Automatización de análisis bioinformáticos con Shell

## Propósito de la unidad

Transformar protocolos reproducibles en herramientas reutilizables mediante scripts de Shell capaces de automatizar análisis bioinformáticos sencillos, validar entradas, organizar resultados y documentar la ejecución de forma transparente.

Al finalizar la unidad, el estudiante será capaz de convertir un protocolo manual en un flujo automatizado que pueda reutilizar con distintos conjuntos de datos biológicos.

---

# Cambio conceptual de la unidad

Hasta la Unidad 4 el estudiante aprendió a responder preguntas biológicas ejecutando comandos uno por uno y documentando cuidadosamente cada decisión.

Ahora aparece una nueva limitación.

Aunque el análisis es reproducible, todavía depende completamente de la persona:

- copiar comandos;
- modificar rutas;
- recordar nombres de archivos;
- repetir los mismos pasos;
- verificar manualmente cada etapa.

La pregunta cambia de:

> ¿Cómo reproduzco correctamente mi análisis?

a

> ¿Cómo construyo una herramienta que reproduzca el análisis por mí?

El protagonista ya no es el comando.

El protagonista es el **flujo de trabajo reutilizable**.

# Competencias que desarrolla

Al finalizar la unidad el estudiante será capaz de:

- distinguir entre un protocolo manual y un script reutilizable;
- utilizar variables para evitar información repetida;
- parametrizar un análisis mediante argumentos de entrada;
- validar archivos y parámetros antes de ejecutar un análisis;
- automatizar tareas repetitivas sobre múltiples archivos biológicos;
- organizar automáticamente productos derivados y resultados;
- registrar la ejecución de un análisis de forma reproducible;
- documentar el uso de un script para facilitar su reutilización.

# Preguntas que responde la unidad

- ¿Cómo evito copiar decenas de comandos cada vez que analizo un genoma?
- ¿Cómo hago que el mismo análisis funcione con otro FASTA o GFF3?
- ¿Cómo verifico automáticamente que existen los archivos necesarios?
- ¿Cómo organizo de forma consistente los resultados generados?
- ¿Cómo proceso muchos archivos sin repetir manualmente los mismos comandos?
- ¿Cómo documento el uso de un script para que otra persona pueda reutilizarlo?

# Filosofía de la unidad

Esta unidad **no es un curso de Bash**.

Shell es únicamente el medio para automatizar análisis bioinformáticos.

Cada nueva construcción debe aparecer porque resuelve una necesidad científica real.

Nunca enseñar una característica del lenguaje únicamente porque existe.

Primero aparece la limitación.

Después la herramienta necesaria para resolverla.

# Documento reproducible

Durante toda la unidad el protocolo continúa siendo el eje del curso.

Ahora incorpora una nueva dimensión:

la automatización.

Cada sesión debe registrar:

- objetivo del script;
- entradas;
- parámetros;
- validaciones;
- comandos automatizados;
- archivos generados;
- pruebas realizadas;
- errores detectados;
- limitaciones;
- interpretación biológica.

No basta con mostrar el código.

Debe documentarse el razonamiento que motivó su construcción.

La unidad puede incorporar, entre otras, las siguientes figuras:

- Procesamiento por lotes de múltiples genomas.

Las figuras deben explicar el razonamiento científico y la organización del análisis, no únicamente la sintaxis del lenguaje.

# Evidencia integradora

## Proyecto final de la unidad

Desarrollar un **script reutilizable** que reciba como parámetros un archivo FASTA y un archivo GFF3, ejecute automáticamente el flujo construido durante la Unidad 4, genere los archivos derivados correspondientes, produzca un reporte resumido y deje un registro suficiente para reproducir completamente el análisis.

El proyecto debe incluir:

- validación de entradas;
- organización automática de resultados;
- mensajes de error claros;
- documentación de uso;
- registro de la ejecución;
- interpretación de los resultados obtenidos;
- limitaciones del flujo implementado.
